# Roadmap M1–M4

> เอกสารฉบับนี้เป็นฉบับภาษาไทยสำหรับการอ่านและสื่อสารภายใน โดยเอกสารภาษาอังกฤษต้นฉบับใน repository เป็น source of truth

อ้างอิง: [roadmap.md](../roadmap.md). M1–M4 แทน future micro-task planning; เอกสารนี้ไม่ใช่การอนุมัติให้ดำเนินงาน. เริ่มได้เฉพาะ scope ที่มีคำขอชัดเจน และต้องหยุดเมื่อ scope นั้นเสร็จ

| Milestone | วัตถุประสงค์ | Entry conditions | Deliverables หลัก | Completion criteria | Safety boundary |
| --- | --- | --- | --- | --- | --- |
| M1 — Portal-native Request Engine | ส่งและติดตามคำขอ access ที่ Portal เป็นเจ้าของ โดยไม่ grant access | implementation scope, request/catalog requirements, authorization policy, DB target/migration scope และ acceptance cases ที่อนุมัติ | lifecycle, catalog/context snapshots, submission/read UI/API, ownership checks, validation, Idempotency, versioned persistence, atomic audit | submission/read ตาม scope ใช้ได้; invalid/unauthorized/duplicate/stale fail safely; ตรวจ snapshot, audit, concurrency แล้ว; ไม่มี Legacy side effect | Portal-only; Legacy `READ ONLY`; ไม่มี production refresh/import, approval execution, Activation, Provisioning/revocation, automation, Entra change หรือ deploy โดย default |
| M2 — Portal Approval Workflow | ตัดสินคำขอพนักงานแบบ audit ได้ โดยแยกจาก configuration governance และ Activation | M1 contracts/tests ผ่าน; identity/reviewer/decision policy และ Portal persistence scope ที่อนุมัติ | rule Resolution/persistence/governance แบบ versioned, exact-version Activation ที่อนุมัติแยก, scoped approvers, ANY/ALL/SEQUENTIAL, decision UI/API, immutable history, drift/retry safeguards | approved routing และ negative cases ผ่าน; unauthorized/stale/replayed/conflicting fail safely; audit rule/version/actor ครบ; drift block ได้; ไม่มี target access change | Portal workflow เท่านั้น; ไม่มี Legacy write, Power Automate change/trigger, Provisioning หรือ revocation; Approval ไม่ execute access change |
| M3 — Controlled VSTS Provisioning Pilot | ดำเนินและตรวจสอบ VSTS access change ที่อนุมัติแบบจำกัด; work-item closure ไม่ใช่หลักฐาน Provisioning | M1/M2 ผ่าน; business/security approval สำหรับ subject/target/permission/execution authority ที่แน่นอน; credentials, verification/recovery criteria ผ่าน review | target/action allowlist, least-privilege connector, dry-run, human execution gate, Idempotency, target verification, immutable audit/correlation, monitoring, stop controls, recovery runbook | approved cases มี verified target outcome และ approval-to-execution audit; duplicate/failure tests ผ่าน; recovery/stop demonstrated; review ก่อนขยายผล | flag ยัง disabled จนกว่าจะมี scoped approval แยกต่างหาก; Legacy SQL, SharePoint, Power Automate ไม่ถูกแตะ; ไม่มี broad sync, revocation หรือ unattended automation โดยนัย |
| M4 — Governance / JML | กำกับ access ตามเวลา ผ่าน Joiner/Mover/Leaver และ access reviews | ผล M1–M3 และ operating controls ผ่าน review; lifecycle/identity sources, owners, privacy/retention, revocation policies และ live read/write/automation authorization ชัดเจน | lifecycle-event design, access review/reconciliation proposals, JML policies, exceptions/escalation, audit/retention reporting, controlled revocation design, simulations, runbooks | JML/review, exception, stale-evidence, ambiguity, recovery tests ผ่าน; audit/retention controls มีหลักฐาน; operators รับ runbooks และ rollout boundaries | default คือ proposals/simulations; ไม่มี bulk import, unattended Provisioning/revocation, Legacy write หรือ Power Automate change จาก observation เพียงอย่างเดียว |

## สถานะ

M1 มีสถานะ `COMPLETE` ณ 2026-09-08. M2, M3 และ M4 เป็น future work และยังไม่เริ่ม. POLICY REQUIRED/dependencies ในเอกสารภาษาอังกฤษต้องได้รับการอนุมัติก่อน milestone ที่เกี่ยวข้องเสมอ
